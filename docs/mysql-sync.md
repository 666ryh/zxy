# MySQL自动同步：本机测试与后续部署

## 已完成
使用MySQL（InnoDB事务），不使用SQLite。账号、会话哈希、各账号教学数据、最近30个修订版都在MySQL。登录后1秒防抖上传、每30秒拉取，网络恢复重试。离线编辑仍先存本机；空新设备登录后恢复服务器数据。

同步包括学生、课程、薪资、课程/上下班考勤、个人资料及头像。背景和辉辉聊天属于设备偏好，本轮不参与同步。访客数据不会直接并入邮箱账号，可先导出教学备份，再登录导入。

冲突不自动覆盖：在“我的→同步与恢复”下载副本后选择本机或服务器版本。采用服务器版本前保留本机恢复副本，服务端保留30次历史。同步面板下载的副本可在数据与备份中导入。多标签页检测到别处更新后停止当前标签同步，需刷新，避免旧页面覆盖。

## 备份与恢复
后台每小时检查当天SQL备份是否存在，缺少时执行mysqldump --single-transaction并压缩。保留最近7天文件，目录server/data/backups。手动执行：
```powershell
npm run backup:db
```

这些备份仍在同一台电脑，必须定期复制到另一设备或网盘才有异地恢复能力。还原前先备份当前数据库，将sql.gz解压为sql，然后使用MySQL客户端导入到新数据库核对后切换DB_NAME；不要未经确认覆盖当前库。已验证压缩备份可恢复到隔离测试数据库。

## 后续服务器部署
准备服务器、已解析域名及开放80/443端口，安装Docker Compose。
1. 拷贝deploy/.env.example为deploy/.env，填写真实域名、不同的强数据库密码及SMTP授权码。
2. 在deploy目录执行 `docker compose up -d --build`。
3. Caddy自动HTTPS，前后端同域名。MySQL端口不映射公网，app端口仅供反向代理访问。
4. `docker compose logs app` 检查；登录验证同步；制定把备份移出服务器的计划。

只在此Compose的私有代理网络启用TRUST_PROXY=true，不要把app:4174直接暴露到公网。考勤日期当前按Asia/Shanghai解释，容器明确设置同一时区。离线工作跨时区暂未支持。

Docker配置已准备，当前Windows环境没有Docker，未实际启动容器。构建使用node22；本机Node18已验证功能。数据库版本：本机MySQL8.3，部署模板MySQL8.4。未来应在目标服务器再做部署验收。

## 验证
`npm test`：业务、登录、同步算法、本机缓存保护测试。
`npm run test:mysql`：使用当前独立实例，在随机测试数据库中验证账号隔离、并发版本锁、幂等、回滚和迁移，结束仅删除本次随机测试库。
浏览器隔离会话验证新增学生自动上传、另一会话恢复；模拟断网修改与另一端写入后出现冲突，采用服务器版本前保留本机副本。错账号同步请求被拒绝。没有通过工具代发邮件。

限制：整文档同步，不逐字段合并；每份教学数据5MB、含头像同步文档6MB。本机同步信封保存基线与待发副本，接近浏览器存储配额时会拒绝写入并提示，请及时导出。部署前需按实际数据量压测与容量规划。
