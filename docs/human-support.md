# 应用内人工客服

用户入口：艳の辉 → 辉辉 → 转人工。登录后在原窗口与人工客服双向聊天，不再跳转微信。

客服网页：https://www.ryh6666.xyz/huihui/ 。独立项目 F:/huihui，UniApp + Vue3，仓库 https://github.com/666ryh/huihui 。客服邮箱 2546619708@qq.com，沿用邮箱验证码登录。服务器 `SUPPORT_STAFF_EMAILS` 控制权限，前端无法自行授予客服身份。

人工消息独立保存在 MySQL `support_threads`、`support_messages`；服务端根据会话 Cookie 认定发件人，用户只能访问自己的会话，客服才能访问列表/回复/结束/已读接口。发送使用 requestId 去重，关闭后须再次转人工才可继续发新消息，旧消息保留。

双方可见网页每 2 秒轮询新消息，断线后自动重新拉取。列表最多显示当前筛选下最新 200 个会话，可按邮箱搜索；此初版适合少量客服接待。单条消息最多 2000 字，每个发送账号每分钟最多 30 条。AI 历史与人工消息分开，转人工不会把此前 AI 对话自动转给客服，也不会暴露教学档案。

工作台静态构建在 `/opt/huihui`，Nginx 同域 `/huihui/` 托管，API 仍由 `kejian.service` 提供，Node 路径 `/usr/bin/node-22`。数据库备份包含客服表。更新客服工作台时构建 `npm run build:h5`，替换 `/opt/huihui` 静态文件并验证 `/huihui/`。后端升级前先备份，新增表继承既有 users.id 字符规则，以兼容本机迁移库。

本次不构建 APK。现有联网 APK 重新打开后加载新版用户界面；也可在正式网页测试。用户与客服建议使用不同浏览器或无痕窗口，避免同域登录 Cookie 相互切换。
