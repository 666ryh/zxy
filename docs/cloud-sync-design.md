# 本地同步后台与部署方案

范围：用户确认暂无服务器，先完成本机数据库、后台、自动同步和部署配置，不打APK、不采购云服务。

数据库：MySQL，账号、哈希会话令牌、每账号当前文档与修订历史。现有accounts.json只做一次非破坏迁移，保留源文件。服务器文件不入Git。单实例部署、InnoDB、事务提交；一致性备份使用mysqldump --single-transaction。

同步内容：完整教学数据（学生/课程/薪资/课程及上下班考勤）+个人资料（含头像）。背景与趣味聊天仅本机。按登录账号隔离，访客不自动上传。首用双方都有独立数据时提示选择；空新设备恢复服务端数据，空服务端上传非空本机副本。

协议：GET /api/sync 返回版本/文档/更新时间；POST /api/sync 带expectedRevision和requestId，事务比较版本并提交、递增版本、保存历史。旧版本返回409且不覆盖。requestId用于丢失响应后的幂等重试。服务端不接受客户端指定userId，始终从HttpOnly会话取身份。

客户端：原同步保存本机API不变，写本机后标记dirty，1秒防抖上传；30秒拉取及联网重试；忙碌时不并发。每个账号本机保存baseline、revision、pending request，页面初始化检查本机是否与baseline不同。切账号以generation取消旧响应。多标签页共享数据时检测存储版本，冲突前后保留副本；本机写入使用单个事务式信封记录数据/资料/同步元数据，原键仅作为迁移源。

冲突：保留当前本机数据，服务端不自动覆盖；提供下载本机副本、采用服务端、上传本机三项，后两项明确确认。覆盖前本机恢复副本写入本地；服务端保留30次变更记录，可下载/恢复，恢复也是新版本。

部署：Docker单服务Node+MySQL持久卷，Caddy HTTPS反向代理，SMTP环境变量，PUBLIC_ORIGIN精确校验、Secure Cookie、请求体上限与鉴权。开发仍4173/4174。数据库每天SQL一致性备份，保留7份；每日快照仅同盘，需要另复制到异地存储才具备灾难恢复。

验收：并发版本拒绝、幂等重试、账号隔离、离线排队、切账号响应隔离、已有数据首次冲突、空新设备恢复、恢复历史不重置版本、旧账号迁移、数据库备份可打开。浏览器两会话模拟不同设备；无真实邮件工具代发。云上线状态明确为“本机同步测试”。
